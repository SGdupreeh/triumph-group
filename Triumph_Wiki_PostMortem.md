## 1. Архитектурный синтез (Почему это сработало)

### Краткое резюме
Успех сессии и достижение качества уровня Awwwards стали возможны благодаря **отказу от стандартного DOM-поведения в пользу физической кинематики**. Интерфейс больше не воспринимается как набор HTML-тегов — он работает как единый физический механизм. Мы добились этого за счет жесткой синхронизации плавного скролла (Lenis) с покадровой анимацией свойств (GSAP ScrollTrigger), а также благодаря переносу тяжелой графики (орбиты, частицы) в Canvas.

### Главные прорывы сессии
1. **Преодоление конфликта React и GSAP:** Мы успешно отказались от привязки scroll-анимаций к состоянию React (State/Re-renders), передав прямое управление мутациями в DOM движку GSAP. Это дало стабильные 60 FPS.
2. **Нулевой CLS (Cumulative Layout Shift):** Решение проблемы с "прыжками" макета при загрузке за счет переноса инициализации ScrollTrigger в `useLayoutEffect`, что позволило браузеру рассчитывать геометрию до первого Paint'а.
3. **Бесшовный Responsive:** Внедрение стратегии "Graceful Degradation" для мобильных устройств (отключение сложных `pin` и `scrub`, замена на нативные CSS-состояния), что спасло UX на смартфонах.

## 2. Технический стек и Инструментарий (Triumph Engine v1.0)

### Ядро (Core Stack)
* **React 18 + TypeScript (Vite):** Быстрая сборка, строгая типизация (исключает ошибки с `RefObject<null>` при передаче элементов в GSAP).
* **Tailwind CSS:** Атомарная стилизация, использование JIT-компилятора для динамических переменных (`lg:top-[var(--card-top)]`).

### Движок Анимаций (Motion Engine)
* **GSAP Core + ScrollTrigger:** Фундамент всей архитектуры. Управление таймлайнами, блокировкой скролла (`pin`), привязкой прогресса к скроллу (`scrub: 1.0`).
* **Lenis (Студия Studio Freight):** Кастомный скролл. Математически сглаживает колесо мыши/трекпад, обеспечивая "тягучесть" интерфейса, необходимую для премиум-сегмента.
* **Framer Motion:** Использовался точечно для микроинтеракций (hover-эффекты, простые модалки, появление элементов без привязки к скроллу).

### Принципы оптимизации
* **GPU-акселерация:** Анимация только свойств `transform` (scale, translate) и `opacity`. Избегание анимации `width`/`height`/`top` для предотвращения перерасчета Layout.
* **Context Manager:** Обертывание всех анимаций в `gsap.context()` для автоматической сборки мусора (Garbage Collection) и предотвращения утечек памяти при unmount-е React-компонентов.

## 3. Инженерия Промптов (Ключ к ИИ)

### Эволюция запросов
**Ошибка в начале:** Использование абстрактных ТЗ вроде "сделай красиво, как на awwwards". Это приводит к дженерик-дизайну с базовыми библиотеками.
**Идеальный формат:** Инженерное ТЗ с метафорами и физическими свойствами. Например: *"Концепция: Агрессивный фокус. Механика: при наведении соседи уходят в opacity 30%, анимация должна ощущаться упругой, как тяжелая пружина".*

### Золотые правила общения с ИИ для CODES Unit:
1. **Описывайте "Физику", а не "Пиксели":** ИИ отлично переводит физические концепции (магнитность, инерция, вязкость, сингулярность) в кривые Безье и параметры `ease: "elastic.out(1, 0.3)"`.
2. **Разделяй и Властвуй (Decoupling):** Никогда не просите "написать секцию с крутым скроллом" за один промпт. Сначала попросите *сверстать статический каркас*, убедитесь в его идеальности, и только следующим промптом требуйте *накатить GSAP*.
3. **Задавайте жесткие ограничения (Constraints):** Прямо запрещайте ИИ использовать плохие паттерны. *"Не используй React State для скролла", "Используй gsap.context", "Обеспечь fallback для mobile (innerWidth < 768)"*.
4. **Контекстный дебаггинг:** При багах давайте максимум контекста. Присылайте скриншоты, куски логов или структуру DOM. ИИ мыслит текстом, визуальный контекст багов адаптива (например, "огромная черная дыра после блока 4") моментально сужает зону поиска ошибки.

## 4. Паттерны Решения Проблем (Troubleshooting)

### Кейс 1: Прыжок макета (CLS 0.94) при загрузке
* **Симптом:** Страница "дергалась" вниз при загрузке.
* **Корень проблемы:** `useEffect` запускал расчеты GSAP (добавляя `pin-spacer` высотой в 2000px) *после* того, как браузер уже отрендерил страницу.
* **Решение:** Глобальная замена `useEffect` на `useLayoutEffect`. Это заставляет React дождаться просчета GSAP перед тем, как отдать финальный кадр браузеру. Сдвиг исчез.

### Кейс 2: Разрушение верстки на мобилках (Огромные пустые пространства)
* **Симптом:** Текст в Манифесте не появлялся, а под карточками этапов (Engine) зияли пропасти.
* **Корень проблемы:** Хардкод классов вроде `opacity-0` в Tailwind и жесткие отступы `style={{ top: ... }}`. На мобильных GSAP отключался и не мог перезаписать эти начальные состояния.
* **Решение:** Изъятие инициализационных классов из HTML и перенос их в `gsap.set()`. Для JIT-стилей внедрение CSS-переменных (`--card-top`) и применение их только через брейкпоинты (`lg:top-[var(--card-top)]`).

### Кейс 3: Ошибка типов TS при сборке
* **Симптом:** Cloudflare не пропускал билд из-за несовпадения типов `RefObject` и неиспользуемых импортов.
* **Корень проблемы:** Строгость компилятора TypeScript в Vite (`tsc -b`). React 18 требует точного указания `HTMLAnchorElement | null` для рефов.
* **Решение:** Инженерная гигиена. Удаление мертвых хуков (`useState`, `useTransform`) после миграции на GSAP, строгая типизация интерфейсов.

## 5. Регламент масштабирования (SOP - Boilerplate-чеклист)

Для запуска следующего проекта по архитектуре Triumph Engine выполняйте шаги в строгом порядке:

1. **[ ] Развертывание базы:** `npm create vite@latest . -- --template react-ts`.
2. **[ ] Интеграция стилей:** Установка Tailwind CSS + настройка `tailwind.config.js` (добавление кастомных `fontFamily` и JIT-цветов).
3. **[ ] Установка Motion Engine:** `npm install gsap framer-motion lucide-react lenis`.
4. **[ ] Инициализация Lenis (Smooth Scroll):** Создание `useLenis.ts`. Запуск глобального `requestAnimationFrame` цикла с интеграцией `ScrollTrigger.update`.
5. **[ ] Разработка компонентов (Статика):** Верстка секций с использованием `min-h-screen`, Flex/Grid. Никаких анимаций на этом этапе. 100% Mobile Responsive.
6. **[ ] Внедрение GSAP Context:** В каждом сложном компоненте добавление:
   ```typescript
   useLayoutEffect(() => {
     const ctx = gsap.context(() => {
       // GSAP Logic
     }, containerRef);
     return () => ctx.revert();
   }, []);
   ```
7. **[ ] Создание ScrollTrigger Timeline'ов:** Настройка таймлайнов с `pin: true` и `scrub: 1` для полноэкранных кинематографичных секций. 
8. **[ ] Graceful Degradation (Мобильные):** Обертывание тяжелой логики GSAP в проверки `if (window.innerWidth >= 1024)` или `gsap.matchMedia()`. Настройка чистых фолбеков.
9. **[ ] Очистка кода & Типизация:** Прогон `tsc -b`. Удаление неиспользуемых переменных, проверка типизации `useRef`.
10. **[ ] QA & Deployment:** Запуск продакшн-билда локально (`npm run build`). Проверка CLS (Lighthouse). Деплой на Cloudflare/Vercel.
